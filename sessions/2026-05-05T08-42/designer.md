### 💻 2. 핵심 와이어프레임 및 컴포넌트 설계

#### A. 메인 배너 (Hero Section)

*   **목표:** 방문자에게 Hooneyz의 가치 제안(Value Proposition)을 3초 안에 명확히 전달.
*   **레이아웃:** 2단 구성 (좌측: 텍스트, 우측: 시각적 요소).
*   **헤드라인 (H1):** 기술 결정 장애, 더 이상 혼자 고민하지 마세요.
*   **서브헤드라인 (P):** 3040 개발자가 실제로 겪는 아키텍처, 비용, 운영 책임의 트레이드오프를 '설계도' 관점에서 풀어드립니다.
*   **CTA 버튼:** [💡 기술 결정 가이드 시작하기] (Primary Color: `#007ACC`)
*   **시각 요소:** '설계도' 느낌의 다이어그램을 배경에 은은하게 배치 (Semi-transparent Grid Pattern).

#### B. 최신 아티클 목록 (Card UI)

*   **레이아웃:** 그리드 3열 배열 (반응형: 모바일 1열, 태블릿 2열).
*   **카드 구조:**
    1.  **썸네일:** 직관적인 메타포 이미지 또는 다이어그램 (직접 제작 권장).
    2.  **태그/카테고리:** `[Tech Wiki]` 또는 `[Deep Dive]` (작은 뱃지 형태, Secondary Color: `#FF9800` 사용).
    3.  **제목 (H3):** (최대 2줄 제한) 예: Microservices vs Monolith, 비용과 운영 책임으로 비교 분석.
    4.  **요약/메타:** (작성자 / 발행일 / 난이도)
    5.  **CTA:** [읽기] (Hover 시 Primary Color로 변화).

#### C. '기술 결정 가이드' 섹션 (Funnel 연동 최적화)

*   **목표:** 단순 아티클 소비를 넘어, 사용자가 '가이드'라는 구조화된 리소스로 이동하도록 유도.
*   **레이아웃:** 플로우 차트 형태의 3단계 비교 구조 (A → B → C).
*   **구성 요소:**
    1.  **헤딩:** ❓ 어떤 아키텍처를 선택해야 할지 고민되시나요?
    2.  **문제 제기 (Pain Point):** "성장 단계에 맞는 최적의 아키텍처는 무엇일까요?"
    3.  **3가지 고민 유형 (Interactive Cards):**
        *   **Card 1 (A):** Microservices vs. Monolith (핵심 고민: 서비스 경계)
        *   **Card 2 (B):** Event Sourcing vs. CRUD (핵심 고민: 데이터 일관성)
        *   **Card 3 (C):** Serverless vs. K8s (핵심 고민: 비용 통제)
